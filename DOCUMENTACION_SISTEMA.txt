                       1. DESCRIPCIÓN GENERAL
===============================================================================

Alliker POS es un sistema de gestión restaurantera completo que integra:

  - Página web pública con carta digital, pedidos en línea y reservas
  - Aplicación de meseros para toma de pedidos y cobros
  - Pantalla de cocina para visualización de pedidos en tiempo real
  - Panel administrativo para gestión completa del negocio
  - Facturación electrónica SUNAT (Boletas y Facturas)
  - Impresión de tickets térmicos con código QR
  - Múltiples sucursales
  - Integración de pagos con Culqi (tarjeta), Yape y efectivo

El sistema está desarrollado en Angular 21 (standalone components) con
Firebase como backend (Firestore + Auth) y desplegado en Netlify.

===============================================================================
                       2. ARQUITECTURA DEL SISTEMA
===============================================================================

  2.1 Frontend
  ---------------------------------------------------------------------------
  Framework:      Angular 21.2.13 con TypeScript 5.9
  Estilo:         Standalone Components (sin NgModules)
  UI:             Bootstrap 5 + PrimeNG 21 + PrimeFlex
  Estado:         BehaviorSubject + Firestore onSnapshot (tiempo real)

  2.2 Backend
  ---------------------------------------------------------------------------
  Base de datos:  Firebase Firestore (NoSQL)
  Autenticación:  Firebase Auth + Custom auth contra colección 'users'
  Hosting:        Netlify (static SPA)
  Serverless:     Netlify Functions (consultas DNI/RUC)

  2.3 Pagos
  ---------------------------------------------------------------------------
  Tarjeta:        Culqi Checkout v4 (Visa, Mastercard, Amex)
  Yape:           Registro manual de código de pago
  Efectivo:       Cálculo de vuelto automático

  2.4 Facturación Electrónica
  ---------------------------------------------------------------------------
  Norma:          SUNAT - UB/L 2.1 (Perú)
  Documentos:     Factura (01) y Boleta de Venta (03)
  Generación:     XML UBL 2.1 + Hash SHA256-like
  QR:             Código QR dinámico con datos SUNAT en tickets térmicos

                       4. ROLES DE USUARIO
===============================================================================

  Rol          | Acceso                        | Funcionalidad principal
  -------------|-------------------------------|------------------------------
  admin        | Todos los módulos             | Gestión completa del negocio
  waiter       | /waiter/*                     | Tomar pedidos y cobrar
  cook         | /kitchen/*                    | Ver y preparar pedidos
  user         | /menu, /cart, /reservations   | Cliente público

  Flujo de autenticación:
  1. El usuario inicia sesión con email+password, Google o Facebook
  2. Firebase Auth verifica la identidad
  3. El sistema consulta la colección 'users' para obtener el rol
  4. Redirecciona según el rol (admin→/admin, waiter→/waiter, etc.)
  5. Guardias de ruta (auth.guard, role.guard, customer.guard)
     protegen cada módulo según el rol

                       5. FLUJO DE PAGO (MESERO)
===============================================================================

  1. El mesero marca la orden como "Entregado"
  2. Abre la pantalla de pago con el total de la orden
  3. Puede dividir el pago entre efectivo, tarjeta (Culqi) y Yape
  4. Calculadora integrada para montos rápidos
  5. Ingresa datos del cliente:
     - Para BOLETA (< S/700): DNI (consulta automática RENIEC) o "Clientes Varios"
     - Para FACTURA: RUC + Razón Social + Dirección
  6. Confirma el pago:
     a. Se registra el pago en Firestore (colección 'payments')
     b. Se actualiza la orden a pagada
     c. Se crea un registro de venta (colección 'sales')
     d. Se genera la factura/boleta electrónica
     e. Se imprime el ticket térmico con código QR SUNAT
     f. Se genera PDF descargable
     g. La mesa pasa a estado "mantenimiento"

===============================================================================
                       6. FACTURACIÓN ELECTRÓNICA SUNAT
===============================================================================

  6.1 Tipos de Documento
  ---------------------------------------------------------------------------
  - Factura (01): Para clientes con RUC. Monto sin límite.
  - Boleta (03): Para clientes con DNI o "Clientes Varios". Hasta S/700.

  6.2 Proceso de Generación
  ---------------------------------------------------------------------------
  1. InvoiceBuilderService.buildInvoiceData() crea la estructura InvoiceData
  2. InvoiceBuilderService.generateUblXml() genera XML UBL 2.1
  3. Se calcula un hash del XML (simpleHash)
  4. Se guarda en Firestore (colección 'invoices') con sunatStatus: "pending"
  5. El ticket térmico incluye código QR con formato SUNAT:
     RUC_EMISOR|TIPO_COMP|SERIE|IGV|TOTAL|FECHA|TIPO_DOC|NUM_DOC|HASH|

  6.3 Correlativos Automáticos
  ---------------------------------------------------------------------------
  - FAC 0001 (F001-00000001, F001-00000002...)
  - BOL 0001 (B001-00000001, B001-00000002...)
  - Los contadores se almacenan en Firestore (colección 'counters')

                       13. SOLUCIÓN DE PROBLEMAS COMUNES
===============================================================================

  Problema                          | Causa probable              | Solución
  ----------------------------------|-----------------------------|---------------------------
  No imprime el ticket              | Popup bloqueado             | Permitir popups en el navegador
  El código QR no aparece           | lastInvoiceData no asignado | Verificar flujo de pago
  Error al consultar DNI            | Netlify Function caída      | Revisar logs en Netlify
  No cargan los pedidos             | Firestore sin conexión      | Verificar conexión a Internet
  Error al procesar pago con Culqi  | API key incorrecta          | Revisar environment.ts
  No se ve el menú público          | Colección vacía             | Agregar platos desde el admin
  Error de compilación              | Dependencias desactualizadas| Ejecutar npm update
